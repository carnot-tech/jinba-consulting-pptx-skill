# PowerPoint（.pptx）にする・既存の資料へ差し込む

> slide-rules.md の §8.6・§8.7 をこのファイルに分けた（PPTX を作るときだけ読む）。番号はそのまま `rules.py --sec 8.6` / `--phase pptx` で引ける。文章・表・1枚1メッセージの規約は slide-rules.md のとおり。

## 8.6 PowerPoint（.pptx）にするとき

**資料は HTML で仕上げる。PPTX にするのは、ユーザーが「PPTX で」「パワポにして」と明示したときだけ。** 編集・修正・レビューの往復はすべて HTML 上で行い、変換は最後に1回だけにする。HTML のほうが直すのも機械チェック（§8）も速く、PPTX で直すと HTML と中身がずれて二重管理になる。PPTX を渡した後に修正が来たら、HTML を直して変換し直す（PPTX を手で直さない）。依頼に PPTX の指定が無ければ、PDF で渡す。

1. HTML で §8 の機械チェック FAIL 0・フレッシュアイ・レビュー（SKILL.md）まで済ませる
2. 変換: `python3 scripts/html_to_pptx.py deck.html`（同じフォルダに deck.pptx。Node 22+・Chrome・python-pptx が必要）
3. `check_deck.py deck.pptx` を FAIL 0 に。PowerPoint で開いて（または PDF に書き出して）文字の折り返しと重なりを目視する。別の形式に移した後は、全ページを画像にして元の HTML と並べて見比べる（三角・矢印・矢羽の形と向きが崩れやすい）。プレビューの表示だけで合格にしない
4. 社外に送るなら、ファイルのプロパティ（作成者・会社名など）を消す
5. 動画（`<video>`）は、元の mp4 が手元にあれば動画として埋め込み、描画された1コマを再生前の静止画にする（Web 上の動画は静止画になる）。変換後のファイルが 10MB を超えると html_to_pptx が WARN を出す。メールで送れないことが多いので、動画・画像を軽くするか、共有リンクで渡す

変換で再現するもの・しないもの:
- 編集できる: 文字（書体・大きさ・色・行間・折り返し幅・箇条書き書式）、塗りと枠（角丸・clip-path の多角形・CSS の三角形）、罫線、表（結合セル・セルの塗り・罫線・余白・縦書き）
- 画像になる（中の文字や数値は編集できない）: SVG のチャート・図、img、背景画像
- CSS の zoom で縮めた部品（追加パーツ集の `.slide` は 0.8 倍）は、文字・行間・罫線・余白にも同じ倍率を掛けて、Chrome で見た大きさのまま書き出す（掛けないと文字だけが 1.25 倍になり、縮んだ箱からはみ出す）
- 書体は和文ゴシック＝Yu Gothic、明朝＝Yu Mincho に置き換える。字幅の差で行末が1字ずれることがあるので、手順3の目視は省かない
- 再現しない: 回転・変形（CSS の transform）、`::before`/`::after` で描いた装飾（背景付きの丸数字など。行頭記号の文字は箇条書き書式として再現する）。これらはパーツ側で使わないか、変換後に PowerPoint で直す

## 8.7 既存の PowerPoint 資料へ差し込むページ

**差し込む先の資料があるときは、その資料のマスターの上で直接組む。** §8.6 の変換は書体（Yu Gothic／Yu Mincho）と版面を自前で決めるので、既にある資料（社内の標準デッキ・作りかけの提案書）へ入れると、書体・文字の大きさ・タイトルの位置・表の作りが浮く。別の書式で作って後から寄せるより、最初から資料に合わせるほうが速い。対象は、ユーザーが PPTX を明示し、かつ入れる先の資料を渡された場合に限る。単独のデッキは §8.6 のとおり HTML で仕上げる。

1. 測る: `python3 scripts/measure_deck.py house.pptx` → `house.skin.json`。本文ページで最も使われているレイアウト（表紙・章扉・本文を 1 枚ずつ並べた見本のように同点なら、中央タイトルでなく後ろで使われるほう。`--layout 名前` で指定もできる）、タイトル・副題の枠、文字の大きさ、書体を run に直指定しているか、テキストボックスの余白と段組み、罫線の色と太さ、表オブジェクトの有無、強調と面の色、ページ番号の出どころを拾う。色は役割（強調・面・丸）ごとに多い順で 3 つまで候補に残す（`color_options`）。資料が HEX で書いた色も、テーマ色かその明暗と一致すればテーマ色に読み替えるので、差し込んだ先のテーマが変わっても色が付いてくる。**値は機械的に拾った出発点なので、要約と資料を見比べて確かめる**（見出しの大きさは外れやすい）
2. 組む: `scripts/deck_pptx.py` の `Deck(資料, skin)`（作例は `examples/house_deck_example.py`）。出力は差し込むページだけのファイルで、土台のスライドは入らない
3. 検査: `python3 scripts/check_deck.py pages.pptx --house house.skin.json` を FAIL 0 に
4. 目視: SKILL.md 手順8の目視と同じ手段で全ページを確かめる。高さは「行数 ×（pt × 1.2 ÷ 72）in」で見積もり、1〜2 行ぶんの余裕を残す
5. 渡す: 資料へ入れるのはユーザー（貼り付けるときに「貼り付け先のテーマを使用」）。マスターが同じなので書式は変わらない。写しへ差し込んで渡すなら `Deck(資料, skin, keep_slides=True)` と `move_slides()`。元のファイルは書き換えない。社外に出す前にプロパティを消すのは §8.6 と同じ（土台の資料の作成者名・コメントの記入者・スライドタイトルの一覧が残る）

資料の作りに合わせる点（§1 のブランドスキンと同じ扱い。ここに無い規約は §0〜§7 のまま）:
- **書体・地色・ページ番号をスライド側に書かない。** 資料がテーマ任せなら run に `latin` / `ea` を書かない（書くと差し込んだ先で書体がずれる）。地色とページ番号はレイアウトが持つ
- **タイトルはレイアウトのプレースホルダーに入れる。** 位置と大きさは資料が決める。資料のレイアウトが副題の枠を持つなら使ってよい（§3 の例外）。タイトルの文の規則（結論を書く・常体・個数を書かない）は §2 のまま
- **表は資料と同じ作りで組む。** 資料が表オブジェクトを使わず、テキストボックスと罫線（見出しの下に太い罫線・行の間に細い罫線・塗りなし）で組んでいるなら、同じに組む。見出しの大きさも資料に合わせ、§6 の「本文より 2pt 以上」は適用しない。塗りなし・縦罫なし・最終行の下に罫線なしは §6 のまま
- **依頼者が「表ではなくテキストボックスと罫線で組む」と指定したときは、資料の作りにかかわらず従う。** 指定が無ければ、資料と同じ作りにする（新規のデッキは §8.6 の変換のまま表オブジェクトでよい）。組み替えた後は、§8 のとおり実物の PowerPoint で開いて修復の警告が出ないことを確かめる
- **色は資料のテーマ色から選ぶ。** `accent2`、`accent2` の lumMod 20%／lumOff 80% のように指定する。資料が役割ごとに色を使い分けているなら、候補から選ぶ（`d.c("emphasis", 1)`）。資料に無い色を足さない。意味を持つ赤（✕）は §5.2 のまま（色は skin の `colors.ng` で変えられる）
- 資料が規約に反する作り（角丸の囲み・下部の結論帯）を持っていても、新しいページで増やさない。資料の決まった型（工程の帯など）を踏襲するときだけ使う

**PowerPoint が開けなくなる不正を、開かせる前に止める。** テーマ色の欄（`schemeClr`）に HEX や存在しない名前を書いた PPTX は、python-pptx では読めても PowerPoint は「修復」を求める。目視のために自動で開かせると、そのダイアログがユーザーの PowerPoint に残り、以後の操作（ユーザー自身の作業も）を止める。`check_deck.py` は PPTX に対してこれを常に FAIL にする。PowerPoint に開かせる前に `check_deck.py --xml-only` で確かめる。
