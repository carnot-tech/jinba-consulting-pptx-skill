# 規約の要点（工程ごと）

`scripts/rules.py --phase <工程>` が表示する要点版。正典は `references/slide-rules.md` で、食い違えば正典が勝つ。各行の §番号は正典の項。詳しく読むときは `rules.py --sec 2.23` で1項だけ、`rules.py --phase <工程> --full` で節全体を引く。

## plan

構成を決める（目的・ストーリーライン・ページの並び）。

- §0 全ページの目的を1行で言えること（言えないページは削る）。調べた量と載せる量を分ける。合意した範囲だけを書く
- §2.23 材料（数字・社内の事実）が無いページは作らず「要確認」と残す。材料の少ないページは隣とまとめ、ページを薄く割って枚数を稼がない（§5.13）
- §2.1 結論をタイトルに書く。1行が基本、長ければ意味の切れ目で2行。文字を縮めて詰めない
- §2.2 タイトルは常体。「です・ます」で終えない（相手に判断・回答を頼むページだけ依頼形で可）
- §2.3 タイトルだけを切り出して意味が通る文にする。主語・対象を省かない。「この」「その」で他ページを指さない
- §2.6 タイトルを上から通し読みして1本の主張になること。§2.8 同じ文型を並べない
- §2.10 図表のページは、図の事実が何を意味するか（So what）をタイトルに書く
- §2.12・§2.19 「現状と課題：〜」のようなラベルの前置きや、作業の説明（「〜を整理する」「〜に分解する」）をタイトルにしない
- §2.4・§2.9 ページの中身の個数をタイトルに入れない。入れた数は本文の数と一致させる
- §2.11・§2.23 断定の強さは根拠に合わせる。例示の数・未確定の段数を確定値のように書かない。根拠の無い試算や「ヒアリングに基づく」などの作った根拠を書かない。判断を左右する数字は一次資料で確かめる
- §2.25 そのページが何についてのページかをタイトルで名指しする。§2.26 判断を求めるページは、結論と読み手が決めることを書き、承認を求める金額は幅だけでも本冊に書く（別紙送りにしない）
- §2.23 試算・計画値は、前提と算式をデッキの中（注か付録）に書き、式を計算し直した結果と本文の数字を一致させる。前提に置いた値（1人あたりの削減時間・単価・削減率）にも出典か根拠を書く
- §2.23 グラフに描く値は原典の数字だけ。図から読み取った概数・相対水準から作った値で描かない（数字の無い項目は文章で書く）
- §3 タイトル直下の説明行・図表の上のラベル行を置かない（例外は図表の軸タイトル1行だけ）
- §4.1 1ページ1メッセージ。§4.13 まとめ（エグゼクティブサマリー）と深掘りを、論点番号と P.n 参照でつなぐ。サマリーと全体マップ・目次で同じ中身を繰り返さない
- §4.45 本文10枚前後なら章扉は要らない（依頼者が求めたら入れる）
- §4.60・§4.96 中身の違うページに同じ作りを使い回さない。同じ見せ方を3枚以上続けない
- §4.103 定番の並び（サマリー→課題→打ち手→ロードマップ→決裁）は使ってよいが固定しない。並びとページの形は目的と材料で決め、材料に固有の発見はそれを主役にしたページにする。課題や打ち手の数を3つに揃えない。タイトルは数でなく中身で書く（「3本柱」でなく柱の名前）。社名と数字を消して別の会社の資料として通る列なら型どおり
- §4.100 付録を付けるなら、本編と付録の間に「Appendix」＋中身1行の区切りのスライドを1枚挟む。付録の各ページは右上のタグなどで付録と示す
- §4.101 方向性が決まった事項を「残る論点」「残る判断」に載せない。論点の一覧はまだ決まっていないものだけにする
- §4.29 懸念・リスクには対応をセットで書く。§4.89 判断を求める資料は、決めてほしいことと推奨を1ページで示す
- §7.16 エグゼクティブサマリーは、各行を「主文1本＋同じ階層の詳細2〜3本」で書き、P.n を添える
- §7.16 エグゼクティブサマリーをページタイトルの羅列にしない。1行だけ太字にしない（全行同じ太さ）
- §9 登壇用のピッチなら `rules.py --phase pitch` も読む。「ピッチ用に作り直して」は文言と並びの依頼で、デザインは残す

## build

ページを組む（配置・余白・色・文字の大きさ）。

- §1 16:9（338.67×190.5mm）、1 section＝1スライド。ボタン・タブなど操作の部品を残さない
- §4.4 左に事実・図、右に意味合い。§4.20 結論やまとめの帯をページ下部に置かない（右の列に書く）
- §4.6 右が図の説明なら見出しは全幅1本にし、右が意味合いのときだけ左右に見出しを分ける
- §4.27 左の事実から右の帰結が導かれる2カラムは、列の間に三角を1つ置く（入れ忘れが最も多い）
- §4.49 左右のカラム見出しは単独で読める名詞句にする。「だから、〜」のような接続詞で始めない
- §4.5・§4.51 左右の列・並べた箱は、幅・高さ・上端を揃える。§4.21 左右の見出しの下罫の高さを揃える
- §4.12 表や箱を縦に引き伸ばして版面を埋めない。箇条書き・決裁の項目・カードの中身も、項目の間を広げて埋めない（space-around・margin-top:auto・height:100% は間延び）。中身が少なければ文字を一段大きくし、上下中央に置くか、前後のページとまとめる
- §5.13 本文は版面の55%以上を使う。ただし空きを埋めるために数字・事例・行を足さない。直し方は、文字を大きくする・配置を変える・ページを統合する。部品の既定の文字の大きさは中身の多いページ向け。中身の少ないページは、書く時点で本文を一段大きく（13〜14pt）するか、前後とまとめる
- §4.54 片側だけ大きく空けない。§4.57 塗りのハイライトは1ページ1か所
- §4.50 塗りは色が意味を持つときだけ。§4.91 列ごとに同じ小見出しを繰り返すなら、左の行軸に括り出して行列にする
- §4.19 同じ役割の文字は同じ大きさ。§6 見出しの大きさは 列・軸の見出し＞行見出し＞本文
- §5.3 角丸にしない。塗りの箱に枠線を付けない。§4.87 意味のない矢印を置かない
- §5.5 色を変えるのは目を向けたい1か所だけ。理由をページの中で示す。色で意味を分けるなら凡例を付ける
- §4.13 右上のラベル（タグ）は、そのページの話題を日本語で書く。部品の型名・伏せ字（「パーツNN｜…」）を残さない
- §4.47 出典・注記は左下の出典行（フッターの1行上）に置く
- §4.95 中身を表さない飾りのイラストを入れない。番号のチップは文字と別の要素にして1文字ぶん空ける

## chart

グラフ・図のページ。

- §5.11 推移・構成比・分布は、表や数字の並びで済ませずグラフで描く
- §5.12 形は見せたい関係から選ぶ: 構成比＝100%積み上げの横棒／項目の比較＝横棒／時系列＝縦棒・折れ線／分布＝縦棒／相関＝散布図／一方の量に応じた他方の量の変化＝折れ線／内訳の移り変わり＝積み上げ面／計算の仕組み（何がどれだけ効くか）＝積み上げ棒・ウォーターフォール。円グラフは区分が2〜3つのときだけ
- 内訳（全体の中の一部、入れ子の値）を、並んだ棒で見せない。積み上げにする
- §5.26 棒は軸の線に乗せ、項目名は線の下に出す。項目名の行数で棒の下端をずらさない
- §5.5・§5.26 棒の色は1色。色を変えるのは目を向けたい1本だけ。色で意味を分けるなら凡例
- §5.18 凡例はグラフの見出しの上に右揃えで置く。グラフの下に置かない
- §3 図表の上に「何の量・単位・期間」の軸タイトルを1行置く（例「国内の利用率、%、2025年」）
- §5.10 上限のある指標（割合・達成率）は0〜上限で描く
- 意味の違う調査の数字を1本のグラフに並べない（並べるなら注記で区別する）
- §2.10 グラフのページは、右の列かタイトルで意味合いを示す

## table

表・行リストのページ。

- §4.10 行＝項目、列＝観点の「軸のある表」にする。カードの羅列で済ませない
- §6 見出し行は本文より3〜4pt大きく太字、塗りなし。最終行の下に罫線を引かない
- §6 列名は、下のセルを1つ指して呼べる自然な名詞にする。「観点」「大項目」「その他」のような種類を指すだけの語にしない。同じ意味の見出しを2行並べない
- §6 見出しの大きさ: 列・軸の見出し＞行見出し＞本文
- §4.102 見出し帯（列見出しの行。多段なら各段）の左端セルに軸の名前（「フェーズ」「ステップ」など）を書く。左上の角も空欄にしない
- §5.2 表のセルを塗るなら、同じ色の凡例チップと意味を同じページに置く
- §4.12 行を縦に引き伸ばさない。セルの上下の余白は3mm前後、行間は文字の1.4〜1.5倍。セルの文字は縦中央
- §4.51 並列の行（論点・料金・役割の表など）は全行同じ高さにする。中身の少ない行も同じ高さで、文字は縦中央
- §6 行の区切り線は縦の区切り線の位置で切る。またがる行は中央ぞろえ＋点線の枠＋凡例。列の間の関係を示す三角・矢印は見出しの軸に1つだけ。塗りの軸ボックスの列には見出しを置かない
- 同じ種類の列（時期・案・部門）は等幅にする
- §6 縦の区切り線は、列の間に意味のつながり（課題→解き方、事実→意味合い）があり見出しに三角を置くときだけ引く。観点を並べただけの列には引かない。引くなら点線で、本文の行だけ（見出しの下罫より上に出さない）
- §6 2列以上にまたがる共通の値は、列をまたぐ点線の枠で括る
- §7.24 1つのセルに1文。§7.25 1文の項目の文末に「。」を付けない
- §6 ○△×やハーベイボールを使うなら、使った段階をすべて凡例で定義する

## process

流れ・工程・ツリー・体制のページ。

- §4.26 矢羽の下に、別の内容の2カラムを積まない
- §4.87 矢印は順序・因果・データの流れを示すときだけ。向きは読む向き（横なら右、縦なら下）
- §5.17 工程の粒度と本数は依頼者・一次資料のものを使う。工程のラベルには動詞を入れる
- §4.77 業務フローはスイムレーンで描く（行＝担い手、横＝時間）
- §4.78・§4.88 イシューツリーは横向きで、各箱を問いの形にする。頂点の問いを、答えを決める要素に分ける
- §4.79 体制図は組織図の形にする
- §4.27 前提→帰結の強い因果は、列の間に三角を1つだけ置く
- §4.98 縦横に項目を並べる図は、軸の名前と両端を図の中に書く

## text

文章を仕上げる。`references/ai-smell-lexicon.md` も読む。

- §7.3 ブレットは1点1行。箇条は2項目以上（1つなら地の文に）。入れ子は各階層2本以上
- §7.19 ブレットは点ごとに切り口（費用・時間・人・手段など）を変える。同じ趣旨の言い換えを並べない
- §7.4 ブレットの語尾は同じ階層で揃え、常体にする（です・ます を使わない）
- §7.9 AI臭い語（「シームレス」「非常に」「〜と言えるでしょう」など）と「 — 」の連結を使わない
- §7.6 1資料1用語。略語は初出で正式名。§7.6 同じ数字はページ間で揃える
- §7.2 見出し・列名・ラベルで勝手な短縮・造語をしない（「アーキ」など）。§7.7 比喩の名詞を本文に使わず、動作や役割で書く
- §7.14 抽象名詞を主語にした受身の文（「量が民主化される」）は、動作主のある文に開く
- §7.32 構造の名前（「現状→理由→帰結」）や読み方の説明（「太字は〜」）を紙面に書かない。脚注に置くのは凡例と出典だけ
- §7.13 後で参照しない番号を振らない
- §7.14 本文でも主語と述語を落とさない（「〜の強化」で終わらせない）
- §7.29 社外の人名には「様」、相手の会社は「貴社」。社内の呼び名・作業の痕跡を残さない
- §7.33 相手の資料・別紙にある項目名は言い換えずに使う
- §7.34 経営層向けの数字は有効数字2桁程度に丸め、「約」「以上」を添える

## check

検査と直し、最後の確認。

- `check_deck.py` と `check_layout.mjs` を続けて回し、FAIL・WARN をページごとにまとめて直してから、もう一度だけ回す。FAIL 0 で終える
- 指摘のメッセージにある § は `rules.py --sec` で引いてから直す
- §5.13 検査の指摘を消すために、中身（数字・事例・行・ブレット）を足さない。直しは形（大きさ・配置・分け方）で行う。指示された箇所だけを直す（手順は SKILL.md）
- §8 PDF にして全ページを画像で見る（目視で確かめる基準）。見る点: 括弧・矢印・三角の向きと矢尻／見出しの下線の位置／図の段と説明の対応／タイトルと図の結論の食い違い／「十分」「限定的」などの評価語の裏付け／目次・P.n 参照とページ番号の整合
- 目視で崩れを見つけたら直す（見て終わりにしない）。直したら検査をもう一度回す
- 報告には、実際に見たページの番号と、残した WARN の理由を書く
